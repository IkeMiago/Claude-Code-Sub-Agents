# /develop — 機能開発コマンド

このコマンドは以下の手順でサブエージェントを連携させて機能を開発します。

## 実行手順

### ステップ1: skillsフォルダーのルールを読み込む

開発を始める前に、必ず `skills/` フォルダー内のすべてのファイルを読み込み、コーディングルールを把握してください。

```
skills/ フォルダー内の全 .md ファイルを読み込む
```

現在確認済みのルール（`skills/code.rules.md`）:
- **ソースコード上のコメントは日本語で作成してください。**

skillsフォルダーにファイルが追加されている場合は、そのルールもすべて適用してください。

### ステップ2: project-planner エージェントで要件定義・計画立案

`project-planner` サブエージェントを起動して、ユーザーの要求から具体的な実装計画を作成します。

**エージェントへの指示内容:**
- ユーザーの要求: `$ARGUMENTS`
- skillsフォルダーのルール（日本語コメント等）を実装計画に含める
- 実装すべき機能の要件・スコープ・タスク分解を出力する
- 技術的制約（例: file://プロトコル対応が必要な場合はES modules不使用 等）を考慮する

### ステップ3: clean-arch-engineer エージェントで実装

`clean-arch-engineer` サブエージェントを起動して、ステップ2の計画に基づいてコードを実装します。

**エージェントへの指示内容:**
- project-plannerが作成した計画を渡す
- skillsフォルダーのルールをすべて適用する（日本語コメント必須）
- 既存コードベースの構造・パターンに合わせて実装する
- クリーンアーキテクチャ原則に従う

### ステップ4: 実装結果の確認・報告

実装完了後、以下を報告します:
- 作成・変更したファイルの一覧
- 各ファイルの役割と変更内容
- skillsルールの適用確認（コメントが日本語になっているか等）
- 動作確認方法

---

## 使い方

```
/develop <作りたい機能の説明>
```

### 例
```
/develop TODOに優先度（高/中/低）をつける機能
/develop ユーザー認証機能（ログイン・ログアウト）
/develop 検索フィルター機能
```

---

## 注意事項

- skillsフォルダーのルールは**常に**適用する（引数に記載がなくても）
- 既存コードを壊さないよう、変更前に必ず現在のコードを読み込む
- `file://` プロトコルで直接開くHTMLアプリの場合、ES modules (`type="module"`) は使用しない
